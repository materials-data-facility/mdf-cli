# MDF v2 Release Burndown — 2026-07-30

Synthesized from a four-agent audit of the three repos (frontend `mdf-next2` @ `design/specimen-phase0`, backend `connect_server/aws/v2` @ `v2-backend-curation`, CLI `mdf_client` @ `v2-simplification`) plus a dedicated end-to-end audit of the legacy→v2 sync path. Every claim below was verified with file:line evidence; live staging endpoints were probed read-only.

**One question from the 2026-07-12 plan is now answered (X1):** both staging gateways (`hjccjf3eqg` and `3xicgt0g7l`) are live, serve identical code (`/openapi.json` path-set hash `bb0886a3e44f4812`, 40 paths) and the same data (`total: 1681`). They are two API Gateway front doors on the same stack — one is orphaned infra. Pick one, document it, tear down the other (see O6).

Legend: **P0** = blocks release · **P1** = fix before or at cutover · **P2** = fast-follow. `[S/M/L]` = rough effort.

## Workstream D — The sync (the release centerpiece; currently 4 manual scripts, no service)

Current state: extract → convert → ingest → reconcile in `connect_server/aws/v2/scripts/`. Strictly one-way (verified: the legacy index UUID `1a57bbe5-…` appears only in the extract script, read-only). But there is **no startup hook, no cron, no admin endpoint, no frontend button, no CLI command, no lock** — Part D of the deployment plan (`sync_prod_to_v2.py`, SSM watermark, content-hash idempotency, 6-hourly cron, `last_synced_at`) is fully specified and fully unbuilt.

- [ ] **D-1 (P0) [S]** Fix watermark data loss: `extract_mdf_production_datasets.py:314-317` advances the `--since` watermark immediately after extract, before convert/ingest run or succeed. A failed ingest permanently skips those datasets. Move the watermark write to after a verified ingest + clean reconcile.
- [ ] **D-2 (P0) [M]** Edit propagation: `ingest_converted_datasets.py:251-256` skips existing store records while search upserts unconditionally (`:247`, `:271`). v1 edits never reach the v2 store, and the store/search diverge permanently on any re-run. Implement the planned `sync_content_hash` compare-and-update (upsert both store and search when the hash changes; skip both when identical).
- [ ] **D-3 (P0) [S]** Safety guard: nothing asserts the write target ≠ the legacy index. Add a hard assertion in `ingest_converted_datasets.py` (and `grant_search_index_role.py:76,122-137`) that the index UUID is never `1a57bbe5-5272-477f-9d31-343b8258b7a5`.
- [ ] **D-4 (P0) [M]** Non-interactive auth: extract uses browser OAuth with a pasted code (`extract:94-121`) — the cron/admin-triggered bridge cannot exist until extract runs on a confidential client with read access to the legacy index. This is the root blocker for every missing trigger.
- [ ] **D-5 (P0) [M]** Build `sync_prod_to_v2.py` per plan D1: wraps extract→convert→ingest→reconcile, SSM watermark `/mdf/{env}/sync-watermark`, never mints DOIs, tombstone-not-delete policy, `source_id` collision guard, `--dry-run` changeset, JSON run report, duplicate-run lock (SSM or DynamoDB conditional write — today two concurrent runs both proceed, and the ingest skip-check is read-then-write TOCTOU).
- [ ] **D-6 (P0) [S]** Scheduling + admin trigger (plan D2/D3): GitHub Actions cron every 6 h gated by a clean `reconcile_migration.py` exit, plus `POST /admin/sync` (curator/admin-gated) so the frontend admin button has an endpoint to call. Surface `last_synced_at`, `synced_count`, `drift_count` in `GET /admin/stats` (`admin.py:30`).
- [ ] **D-7 (P0) [S]** Frontend admin surface: no `/admin` route or sync button exists on any of 18 branches in `mdf-next2`. Add an admin page (gate on the existing server-side curator check pattern from `useCurator.ts`) with a "Run sync" button → `POST /admin/sync` and a sync-health card fed by `/admin/stats`.
- [ ] **D-8 (P1) [M]** True parity check: `reconcile_migration.py` compares converted-JSON vs v2 — it never queries the legacy index, so anything dropped at extract/convert is invisible. Add a legacy-vs-v2 mode: record counts, per-`source_id` presence, and field-level diff (title/authors/DOI/keywords) sampled or full. Also make it exit non-zero when the search check is unavailable (`:71-74` currently degrades silently to exit 0).
- [ ] **D-9 (P1) [S]** Make `convert_production_datasets.py` exit non-zero on per-entry conversion errors (currently always exit 0, `:227-238`); add retry/backoff to extract and `batch_ingest` (currently zero retries anywhere — one transient 5xx aborts extract and loses all partial work); add a `sort` to the extract query (`extract:145-151` is unsorted offset pagination — live v1 ingests during a long extract silently skip/duplicate rows).
- [ ] **D-10 (P1) [S]** Fix `--dry-run` skipping `build_submission_record` (`ingest:243-244`) so dry runs exercise the GSI-key edge cases; print a changeset ("N created / N updated / N skipped") not just counts.
- [ ] **D-11 (P1) [S]** Tests: zero tests import any sync script; `test_v2_legacy_redirect.py:77` hand-stamps `legacy_source_id` instead of producing it via the ingest code. Add unit tests over `convert_entry`, `build_version_chains`, `build_submission_record` with real v1 gmeta fixtures, and one end-to-end sqlite-backed sync test.
- [ ] **D-12 (P2) [S]** Cosmetic-but-misleading: `extract` `summarize()` reads the old gmeta shape (`:186-196`) so the operator sanity summary prints empty; entries with unparseable `ingest_date` are silently dropped by `--since` filtering (`:277-280`).
- [ ] **D-13 (P2) [M]** Coverage gaps to decide explicitly (document as accepted or fix): only `resource_type=dataset` is synced; no deletion/withdrawal propagation (no tombstones); organizations collapse to first string; migrated records have `user_id="v1-migration"` so original submitters can't edit (`cards.py:47`), no `user_email` (emails no-op), no `metadata_updated_at` (embedding staleness check blind); silently manufactured values (`"Untitled"`, `[{"name":"Unknown"}]`); v2 GMeta omits `mdf.resource_type` so the migration query returns zero rows against v2.
- [ ] **D-14 (P1) [S]** Resolve the contradiction: `MANUAL_TEST.md:5` says 904 datasets already ingested on staging; `.continuity/production-readiness.md:134-135` says the pipeline was never exercised at scale. Confirm which is true before cutover.

## Workstream B — Backend (`connect_server/aws/v2`)

- [ ] **B-1 (P0) [M]** File upload/download is entirely non-functional: streams router is commented out (`app/__init__.py:64,67`) but `files.py`/`preview.py` stay mounted and every handler 400s on the stream lookup (`files.py:52-54,161,199,250,286`; `preview.py:29,66`). Either re-enable the stream lifecycle endpoints or unmount/rework the dependent routers — and align README/`FRONTEND_API.md`/CLI, all of which advertise these as working.
- [ ] **B-2 (P0) [M]** Search subject collision: `search_client.py:72` builds subjects with no version component, so all versions of a dataset collide on one search entry, and `_update_prior_versions_search` (`async_jobs.py:454-477`) overwrites the *current* entry with the prior version after publish. Corrupts normal publishing, not just migration. Add version to the subject (or one-entry-per-dataset with explicit latest semantics) + a subject-uniqueness test.
- [ ] **B-3 (P0) [S]** Ownership hole: `POST /submit` with `update: true` never calls `ensure_submission_owner_or_curator` (`submissions.py:519-522` vs `:204,310,371`) — any submitters-group member can push a version onto anyone's dataset and flip its `latest` flag. Migrated records (owner `"v1-migration"`) are maximally exposed. Add the owner/curator check.
- [ ] **B-4 (P0) [S]** SQS failures never reach the DLQ: handler returns `batchItemFailures` (`async_jobs.py:723-733`) but the event source mapping lacks `FunctionResponseTypes: [ReportBatchItemFailures]` (`template.yaml:354-360`). One-line template fix.
- [ ] **B-5 (P0) [S]** Rotate the DataCite credential committed in git history (`git show 648dd9b:aws/samconfig.toml` lines 50/64) — rotation, not just removal.
- [ ] **B-6 (P0) [S]** Enable DynamoDB point-in-time recovery on both tables (`template.yaml:484-570`) **before** any bulk migration write to prod.
- [ ] **B-7 (P0) [S]** Publish pipeline integrity: `status=published` is set even when search ingest fails (`async_jobs.py:517-539`, warning only); DOI minting has no idempotency key on an at-least-once queue → double-mint on redelivery (`:565-576`). Gate the status flip on ingest success; make DOI mint idempotent (check-before-mint or a dedup key).
- [ ] **B-8 (P0) [S]** Fix the 5 failing tests at HEAD (3 × `TestDomainsAndExternalImport` stale against the nested `external` model; 2 × disabled `/stream/create`) and point `make test` at the v2 suite (`aws/Makefile:41-42` runs the v1 `tests/` dir). A red suite means CI gates nothing.
- [ ] **B-9 (P1) [S]** OpenAI key has no deploy path: `OpenAIApiKey` defaults to the literal `"not-configured"` (`template.yaml:163-167`), is absent from `samconfig.toml`/`deploy.sh`/README, and `embeddings.py:60-66` only rejects empty strings — semantic search 401s opaquely in staging and prod. Add SSM resolution in `deploy.sh` and reject the sentinel value at startup.
- [ ] **B-10 (P1) [S]** `POST /embed` is unauthenticated and bills OpenAI per call (`search.py:135-148`); only the in-memory 120/min limiter protects it — and that limiter is per-container so the effective limit is ~10× (`middleware.py:16-17,72-85`). Require auth on `/embed`.
- [ ] **B-11 (P1) [M]** Observability: zero CloudWatch alarms in the template. Add alarms for Lambda errors, DLQ depth, SQS message age, and Dynamo throttles + an SNS topic before cutover.
- [ ] **B-12 (P1) [M]** Deploy hardening: no CI deploy path for v2 (prod ships from a laptop via `deploy.sh prod`, no confirmation prompt, secrets passed on the command line, `deploy.sh:240-252,435-438`). Add a GH Actions deploy workflow (OIDC to AWS), a prod confirmation gate, and stop passing secrets as CLI parameter-overrides.
- [ ] **B-13 (P1) [S]** `MetadataEditRequest` (`models.py:100-118`) lacks `external`, `download_url`, `data_sources`, `publisher`, `publication_year`, etc. — the fields central to migrated records can't be corrected via the API after ingest. Extend the model.
- [ ] **B-14 (P1) [S]** Config footguns: prod's `TestSearchIndexUUID` is the staging index (`samconfig.toml:71`); `USE_MOCK_*` keyed on `AuthMode` not `Environment` (`template.yaml:228-238`); `config.py:5` default table name ≠ deployed name; DOI landing URLs hardcode the portal domain instead of `PORTAL_URL` (`curation.py:76`, `search_client.py:15`).
- [ ] **B-15 (P2) [S]** Bundle hygiene: `CodeUri: .` ships all of v1, the test suites, and demo scripts in the Lambda package (`template.yaml:205,302`); add `.samignore`. `MANUAL_TEST.md` dev-auth steps can't pass under staging's `AuthMode=production` — rewrite with real tokens.
