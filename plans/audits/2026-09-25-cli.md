# MDF CLI launch-readiness audit (mdf-cli 0.3.0, `cli-styling` @ 0e17769)

Method: I dumped the full Typer/click tree (95 entries, including hidden ones) and ran `--help` on every command. I ran read flows against staging twice: logged out (sandboxed `HOME`) and as the real cached login (read-only). I read `src/mdf`. I ran no publish, submit or write commands and no tests. Items already closed in the burndown are not repeated here.

## 1. Command inventory

86 leaf commands, of which **47 are hidden (55%)**: 19 top-level aliases, 18 under `backend`, 7 under `stream` and 3 under `manifest`.

Every networked command repeats `--service --api-url --token --dev-user`. The tree declares these by hand about 40–65 times, and they show up in every `--help`.

## 2. UX and flow issues, ranked

**U1. `mdf show` crashes on every real dataset. [S] Blocker.**
- Evidence: `mdf show bennett_origin_metalinsulator_metals` prints a Rich traceback: `TypeError: sequence item 0: expected str instance, dict found` at `main.py:2206`. The same happens for `darpa_sd2_perovskites`, `stanley_machine_learning_photovoltaics`, `perovskite_opbandcenter` and `--cite`.
- Cause: the card API now returns author objects (`{"name","given_name","family_name","affiliations"}`). The same bug is in `backend.py:446`.
- Fix: add one `format_authors()` helper in `theme` or `formatting`, and use it at both sites and in `main.py:2958`.
- Also: `show --json` double-nests the card (`{"success":true,"card":{"success":true,"card":{…}}}`), and `test_cli_json_contract.py:188` pins that shape. Flatten it before 1.0.

**U2. Authenticated commands start an unstyled interactive Globus prompt instead of failing fast, even under `--json`. [M] Blocker.**
- Evidence: logged out with stdin closed, `mdf list --json`, `mdf status <id>`, `mdf admin stats --json` and `mdf clone X --plan --json` all print `Visit this URL, sign in, and paste the code: … Enter the resulting Authorization Code here: Aborted.` **on stdout**, exit **1**, and emit no envelope.
- This breaks the exit-code and JSON contract in the CHANGELOG (auth failures should exit 4).
- Cause: `BackendClient.authenticated` falls through to interactive login (`backend_client.py:110-125`, step 5), and `auth/globus.py:240,280` uses `print()` to stdout.
- Fix: an `interactive=` parameter plus an `AuthRequired` exception in core. The CLI only prompts when stdin and stdout are TTYs and `--json` is off. Otherwise it returns kind `auth` with exit 4 and the hint `mdf login`. Prompt text goes to stderr.

**U3. Public clone does not work without Globus, and `--plan` hangs. [L, cross-repo] Blocker for "find and reuse".**
- Logged out: `mdf clone bennett_… --plan` prints a raw tuple, `Warning: Failed to list /mdf_open/…_v1.1/: ('GET', 'https://transfer.api.globus.org/…', 'Bearer', 400, 'ClientError.BadRequest.MalformedAuthHeader', …)`, then drops into the login prompt from U2.
- Logged in: the same `--plan` printed **nothing in 8 minutes**, at which point I killed it. `lsof` showed it holding a connection to the Globus Transfer load balancer.
- Cause:
  - Migrated records have a directory `download_url`, so `archive_available=False` (`agent.py:~1640`).
  - The code then calls `_resolve_globus_files`, which runs an unbounded recursive Transfer `operation_ls` with an empty token (`agent.py:562-660`).
  - `_ls_recursive` swallows failures with a bare `print` (`agent.py:645`), so partial clones pass silently.
  - The v2-native `de6b89c7…` shows the same path, with a doubled `//mdf_open/…`.
- Fix:
  - Backend: expose a per-file HTTPS manifest (or zip) on the card, so public clone needs no Transfer token.
  - CLI: make `--plan` card-only (no listing unless `--files`); add a spinner with a file counter and a wall-clock cap; raise on ls failure.

**U4. `--update` doesn't find the dataset on its own, and the paths that work use a deprecated key or drop metadata. [M] Blocker if documented.**
- `README.md:140` says `mdf publish --update --submit  # Updates last published dataset`. That is false:
  - `publish()` (`main.py:1074-1305`) never reads `last_publish.source_id`.
  - `ManifestConfig` has no `source_id` field.
  - Unless `mdf.yaml` hand-carries an identity, the backend returns `400 Missing source_id for update submission` (`connect_server …/submissions.py:1094`).
- I verified this by reading code, not by a dry run. Running `mdf publish`, even as a dry run, was blocked by the permission classifier in this session.
- The shipped skill works around this by having agents write `custom.mdf_source_id` (`SKILL.md:197,236`). That becomes `extensions.mdf_source_id`, which the backend accepts only as a **deprecated** alias (`submissions.py:131-135`).
- The hidden `mdf update <ID>` does find the dataset automatically, through the same deprecated key (`main.py:2753`), but:
  - it rebuilds the manifest from only title and authors (`main.py:2742-2751`);
  - the backend expects full metadata on submit and inherits only `data_sources`, the ACL and the DOI, so **the new version drops description, keywords, license, funding and related works**;
  - it swallows card-fetch errors (`main.py:2741` `except Exception: pass`) and then uses the source_id as the author name.
- Fix: one update path, `mdf publish --update <ID>` (default: `source_id` from `mdf.yaml`, then last publish). It should fetch the full prior metadata, merge overrides, and send a top-level `source_id`. After the first successful publish, write `source_id` back into `mdf.yaml`.

**U5. IDs are truncated in every table, which makes the next command impossible to type. [S]**
- `search` truncates to `bennett_origin_metalinsulat…` (`main.py:1720`, `max_width=28, no_wrap=True`), while the title wraps to 8 lines at 100 columns and still wraps at 140.
- `list` shows `mdf-fe1de378a4264052901a0a5…`, the user's own generated IDs, and there is no other way to get them except `--json`.
- `related` truncates the same way.
- A null DOI renders as the literal `None` (`main.py:1727`).
- The `Type` column is always "dataset" (streams are off), and every Status in public search is "✓ published".
- `id v1.0` is glued into one cell.
- Fix: put the ID first and never truncate it; show the title on one line with an ellipsis; drop Type and Status from public search; show `—` for null; move the version to its own column or leave it out.

**U6. `cite` output is unusable in pipes and files. [S]**
- `mdf dataset cite X -f bibtex > refs.bib` writes box-drawing borders and hard-wrapped `author = {…}` lines into the file.
- `-f nonsense` silently falls back to APA with exit 0 (`dataset_cmd.py:116`).
- Fix: print raw text to stdout (panel only on a TTY), add `-o FILE`, and make `--format` an Enum.

**U7. Hidden and visible names are inverted, and hints point at commands that don't exist. [S–M]**
- The shipped skill and hints use the *hidden* names: `mdf validate` (`SKILL.md:154`), `mdf edit` (`SKILL.md:229`), `mdf manifest discover/inspect` (`manifest_cmd.py:133,190,201`), and `setup`'s next steps (`main.py:803`).
- `publish` suggests `mdf config validate`, which **does not exist** (`main.py:1211`).
- Nothing is on PyPI yet, so there is no back-compat obligation behind the 19 aliases.
- Fix: pick one canonical name per action (see §4), delete the rest, and add a test that every `mdf …` string in `src/`, `README.md` and `skills/` resolves in the click tree.

**U8. Exit codes and validation are inconsistent. [S]**
- `related <bad-id>` returns "no relations" with exit 0 instead of exit 3.
- `import zenodo:10000000` (404) and an unregistered DOI exit **5** (network), and leak the raw httpx text `For more information check: https://developer.mozilla.org/…`.
- `search --type bogus` returns empty with exit 0, but `--sort bogus` exits 2.
- Direct-mode `publish` without `--title` exits 1 and prints a Rich panel even under `--json` (`main.py:1116-1125`, `1164`).
- `config doctor` exits 0 with three ✗ rows.
- `--json --brief` returns a bare list with no `success` key, which contradicts the CHANGELOG, and it omits `source_id`.
- `--limit 500` is clamped to 50 without notice.
- Fix: Enums for `--type/--format/--sort/--by/--client`; importers map 404 to `not_found`; route every early exit through `json_fail`.

**U9. `list` defaults are noisy. [S]**
- Live: my top 5 rows were all `○ deleted` `[E2E-TEST]` records.
- One dataset (`de6b89c7…`) takes 10 rows, one per version.
- Timestamps are raw ISO strings.
- Fix: latest versions only and hide deleted or withdrawn records by default (`--all` to show them); use relative dates; add a "Next: mdf status <id>" hint.

**U10. First run and setup need work. [M]**
- The welcome panel lists `publish --submit` before `login`.
- `setup` asks for the service as free text (no validation). It asks for "Publisher" and then **uses it as the default Author** (`main.py:777`). It takes one author only, asks nothing about license or keywords, and never offers to log in.
- It **always persists `defaults.service=staging`** (`main.py:715`), and `mcp install` bakes `MDF_SERVICE: staging` into client configs (`mcp_cmd.py:79`). When the default flips to prod, every early adopter stays pinned to staging without being told.
- `login` and `status --auth` never say *who* you are.
- `login --token` validates the token but doesn't store it ("this invocation only", `main.py:891`), so the command does nothing lasting.
- `logout` prints twice: `globus.py:309` plus the CLI.

**U11. Noise and consistency. [S each]**
- "MDF Agent" branding appears 18 times, including the `mdf --help` header and the welcome title.
- Streams leftovers: `search` help says "datasets and streams" and shows `--type streams`, and `README.md:3` says "stream data from automated labs".
- The `mcp` group sits in an unlabeled "Commands" panel above "Auth & Setup" (`main.py:113`).
- `versions` suggests `diff --from 1.0 --to 1.0` for single-version datasets (`dataset_cmd.py:362`).
- `related --by similar` passes through "Run `mdf admin rebuild-embeddings`", a curator-only command, to end users.
- Also minor:
  - "Next: a | b" hints read like shell pipes;
  - `status` uses plain `Label:` lines instead of the shared detail view;
  - `import 10.18126/…` (MDF's own DOI) offers to re-import it with "0 files";
  - `--dev-user` is visible on about 40 commands.

## 3. Code-design issues, ranked

**D1. Core does interactive I/O. [M]** `BackendClient.authenticated` can prompt (`backend_client.py:110`). `globus.py:240,280,309` and `agent.py:187,254,607,645,1294,1316` call `print()`. The SDK, the skill handlers and the CLI therefore all inherit hidden prompts and stdout pollution. Fix: core raises or logs, and the CLI renders.

**D2. `cli/main.py` is 3,148 lines, and 20% of it is duplicate aliases. [M]**
- `main.py:2255-2897`: 19 hand-copied alias signatures. `update_alias` is a 210-line fork of `publish`.
- Repeated declarations across `cli/`: 65× `--api-url`, 59× `--json`, 41× `--token`, 40× `--dev-user`, 36× `resolve_service(`, and 55 manual `client.close()` calls, some without `finally` (`dataset_cmd.py:107`).
- Fix:
  - `cli/options.py` with `Annotated` aliases (`ServiceOpt`, `JsonOpt`, …);
  - a `with open_client(ctx, public=True)` context manager;
  - split into `cli/commands/{auth,publish,clone,search,show,list,status,import}.py`.

**D3. Three parallel surfaces use three error envelopes. [M]**
- CLI: `{"success":false,"error":{kind,code,message,hint}}` (`formatting.py`).
- Skill handlers: `{"success":false,"error":"<str>","error_type","kind"}` (`skill/handlers.py:17-41`).
- MCP: `{"error":{…}}` with no `success` key (`mcp/server.py:190`).
- MCP imports `is_success` and `classify_api_error` from `mdf.cli.formatting` (`server.py:201,238`), so a protocol server depends on the CLI presentation layer.
- `mdf.skill.handlers` and `TOOLS` have **no consumer in `src/`**. They call `BackendClient.authenticated` even for public reads (`handlers.py:44-66`), which means an interactive login inside an agent. They also still carry 5 stream tombstones.
- Fix: move the result and error types to `mdf/core/errors.py`. Either delete `mdf.skill` or rebuild it and MCP on one `mdf/services/` read layer. The `mdf/skill` vs `mdf/skills` naming collision also goes away.

**D4. Dead or dev surfaces ship in the wheel. [S]** `cli/stream.py` (338 lines), `cli/backend.py` (550 lines, including write commands with no help text and a second copy of the author-join crash), `MDFAgent.stream_*` (`agent.py:1106-1216`), BackendClient stream methods, and `formatting.json_or_rich` (unused). Delete them.

**D5. Tests drift from the live API. [M]**
- The `show` fixtures have no authors (`test_cli.py:736`, `test_cli_json_contract.py:181`). That is how U1 shipped with a green suite.
- Tests pin shapes that should change (`card.card`, bare-list `--brief`).
- These are never invoked: `setup`, `update`, `edit`, `withdraw`, `watch`, `mcp install/serve` (CLI).
- Test files are organized by audit wave (`test_cli_review_fixes.py`), not by module.
- Fix:
  - recorded staging fixtures (card, search, versions, citation, list) under `tests/fixtures/staging/`;
  - one parametrized contract test: every `--json` command, logged out with stdin closed, must print parseable JSON on stdout and exit with a code in {0,2,3,4,5};
  - a `--help` snapshot test;
  - a nightly read-only staging smoke run (`search/show/cite/versions/clone --plan`).

**D6. Service resolution leaks. [S]** The private `_api_url_for_service` is imported across layers (`main.py:30`). `dev` points to an NXDOMAIN host but is still advertised. The persistence problems in U10. `prod` is still dead (`curl` timed out; C-1/O-5 still open).

## 4. Target command tree and first-run flow

```
Get started   login · logout · whoami (identity + service) · init [PATH] · doctor
Find & reuse  search [Q] · show ID [--files] [--cite] · cite ID [-f] [-o] · clone ID [DIR] [--plan] · related ID · versions ID
Publish       check (was validate/--preflight-only) · publish [--submit] [--update ID] · status [ID] [--watch] · list [--all] · import DOI|zenodo:N
Manage        dataset edit|withdraw|resubmit|diff|open
More          admin … · config show|get|set|path · manifest discover|inspect · skill … · mcp …
```

- `init` merges `setup` and `manifest init`: prompts on a TTY, flags otherwise.
- Delete `backend`, `stream` and the 19 aliases.
- Hide `--dev-user`, and make `--api-url` env-first.

First run:
1. `pipx install mdf-cli`
2. `mdf` shows three paths: **Find data** (`mdf search`), **Publish** (`login → init → check → publish --submit`) and **Agents** (`skill install`, `mcp install`).
3. `mdf login` ends with "Logged in as <name> <email> · staging".
4. `mdf init ./data` asks for title, authors (repeatable), description, license (choice) and keywords, then offers to log in.
5. `mdf check`
6. `mdf publish --submit` shows progress, writes `source_id` into `mdf.yaml`, and watches until pending.
7. `mdf status`, `mdf show <id>`, `mdf cite <id> -f bibtex -o ref.bib`.

## 5. Launch blockers

1. U1: the `show` crash.
2. U2: implicit login breaks `--json` and exit-code 4 (list/status/admin/clone).
3. U3: public clone needs Globus login, and `--plan` hangs. At minimum, make `--plan` fast and non-interactive, and document that clone requires login.
4. U4: the README's update command fails for a human (it doesn't find the last published dataset). The working paths depend on a deprecated identity key, and the hidden `mdf update` drops metadata. Fix it, or pull it from README and skill.
5. U10: `setup` and `mcp install` pin users to staging. Fix before any user runs them, because the pin is invisible later.
6. Still open from the burndown: C-1/O-5 (prod host dead). Staging is also missing the embedding snapshot (`related --by similar` fails) and preview profiles (C-7).
7. Hygiene to check: the tracked `context/RPPR Supplemental - MDF Phase IV - April 2026.md` (a grant report) will be public if the repo is.

## 6. Suggested ordering (1-week window)

- **Days 1–2, correctness and contract:** U1 (author helper everywhere), D1/U2 (`AuthRequired`, prompts to stderr, no prompt when non-TTY or `--json`), U4 (one update path with top-level `source_id`, metadata merge, write-back), U3 CLI half (card-only `--plan`, spinner, timeout, raise on ls failure), U6, U8. Add the D5 recorded fixtures and the `--json` contract test the same days, so every fix lands with a test.
- **Days 3–4, surface and design:** delete the aliases, `stream`, `backend` and (decision needed) `mdf.skill` (D2, D3, D4). Canonical names plus a test that every hint resolves (U7). Table fixes (U5), `list` defaults (U9), the `setup`→`init` rework, `whoami`, and no service pinning (U10). Then U11 polish and the branding sweep. Update README and `SKILL.md` to match.
- **Day 5, structure and guardrails:** split `main.py` behind shared options and a client context manager; move errors to `core/errors.py`; `--help` snapshot tests; a nightly staging smoke run in CI. Start the backend ask for a public per-file manifest (U3, backend half) in parallel, since it gates true anonymous clone.
